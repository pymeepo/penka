# «Пенка» — демо-сайт кофейни

## Цель
Демо-сайт вымышленной сети кофеен «Пенка» (3 точки в одном городе) для портфолио.
Потом сайт оборачивается в мобильное приложение (WebView), поэтому в нём есть страницы,
показывающие возможности приложения: вход с сохранением сессии (cookie), корзина, форма
с загрузкой фото, страницы акций (цели пушей), звонок, карты, мессенджеры, скачивание PDF.

## Стек
- Astro 7 (статическая сборка) + TypeScript strict + Tailwind CSS 4 (через `@tailwindcss/vite`,
  `src/styles/global.css` с `@import "tailwindcss"`, токены в `@theme`, без tailwind.config).
- Интерактив — чистый TypeScript в `<script>` компонентов Astro. **Никаких React/Vue/Svelte.**
- Шрифты локально из npm: `@fontsource-variable/manrope` (текст), `@fontsource-variable/unbounded`
  (заголовки). Никаких внешних CDN, Google Fonts и т. п.
- Иконки — inline SVG (пути из lucide), без иконочных шрифтов.
- Картинки — `<Image>`/`<Picture>` из `astro:assets` (avif/webp, явные размеры).
  Фото лежат в `src/assets/images/` (не в `public/` — иначе Astro их не оптимизирует).
  В данных фото указываются ключом (`image: 'cappuccino'`), в Astro — `await loadImage(key)` из `src/lib/images.ts`.
- Node 26 LTS (см. `.nvmrc`, nvm-windows).
- PDF-меню — `pdf-lib` + `@pdf-lib/fontkit`, шрифт с кириллицей, генерируется скриптом перед сборкой.
- Тесты — Playwright (мобильный вьюпорт), Lighthouse CLI.
- Хостинг — GitHub Pages через GitHub Actions (`withastro/action`), репозиторий `penka`.

## Команды
- `npm run dev` — дев-сервер (http://localhost:4321/penka/)
- `npm run build` — PDF-меню (`npm run pdf`) + `astro check` + сборка в `dist/`
- `npm run pdf` — `public/files/menu.pdf` из `src/data` (pdf-lib, WOFF-шрифты fontsource по подмножествам; не коммитится)
- `npm run preview` — просмотр сборки
- `npm run assets` — логотип (SVG/PNG), иконки PWA, OG-картинка, заглушки для недостающих фото (`scripts/`).
  Логотип рисуется кодом в `scripts/lib/brand.ts`; PNG для приложения — в `brand/`.
- `npm run test` — Playwright (Pixel 7) против собранного сайта (`astro preview` на :4322): смоук всех страниц,
  режим приложения, мост `postMessage`, заказ, вход/cookie, маска телефона; скриншоты в `screenshots/`.
  Сначала `npm run build`.
- `npm run lighthouse` — Lighthouse mobile по 10 страницам (`astro preview` на :4323, Chromium из Playwright);
  отчёты в `.lighthouse/`, код выхода 1, если оценка ниже цели

## Правила
- Тексты на сайте — на русском, цены в рублях (`350 ₽`). Код, имена файлов, коммиты — на английском.
- **Base path `/penka/`.** Все внутренние ссылки и ресурсы — через хелпер `url()` из `src/lib/url.ts`
  (обёртка над `import.meta.env.BASE_URL`). Никаких захардкоженных `href="/..."`.
- `site` и `base` задаются одной строкой `SITE_URL` в `site.config.mjs`. При переезде на свой домен
  меняется только она (+ `public/CNAME`).
- В `public/` лежит `.nojekyll`.
- Данные — только в `src/data/*.ts` (меню, акции, точки). Страницы их не дублируют.
- Телефоны заведомо фиктивные: `+7 000 000-00-00`. Мессенджеры — только share-ссылки
  (`https://t.me/share/url?url=…`, `https://wa.me/?text=…`), никаких чужих аккаунтов.
- На каждой странице (подвал) и на контактах — плашка
  «Демо-проект: кофейня вымышленная, заказы не принимаются».
- Mobile-first: главный сценарий 360–430 px; на десктопе контейнер до 1200 px.
- Анимации спокойные, всё движение выключается при `prefers-reduced-motion: reduce`.
- Персональные данные (корзина, профиль, история заказов) — только в браузере (localStorage, cookie).

### Режим приложения (WebView)
- Включается, если у `<html>` есть класс `in-app` или в user agent есть `PenkaApp`
  (инлайн-скрипт в `<head>` добавляет класс до отрисовки).
- В режиме приложения скрыты шапка, подвал и баннер «Скачайте приложение»; добавлены отступы
  `env(safe-area-inset-*)`.
- Элемент `.cart-count` **всегда остаётся в DOM** (приложение читает из него число для бейджа).
- При изменении корзины, если есть `window.ReactNativeWebView`, отправляется
  `postMessage(JSON.stringify({ type: 'cart', count }))`. На обычном сайте — ничего.
- Сессия: cookie `penka_session`, `Max-Age=2592000` (30 дней), `Path=/`, `SameSite=Lax`.

### Бренд
- Палитра: фон `#F7F1E8`, текст `#2B1D14`, акцент `#C8875B`, второй акцент `#8FA58A`.
- Карточки скруглены 16–24 px, мягкие тени, крупные фото, много воздуха. Тон тёплый, без пафоса.

### Качество
- Lighthouse mobile: Performance ≥ 90; Accessibility, Best Practices, SEO ≥ 95.
- Title, description, Open Graph на каждой странице; PWA-манифест; `meta theme-color`.
- Playwright: все страницы открываются в мобильном вьюпорте без ошибок в консоли.

### Подводные камни
- Дев-сервер Tailwind 4 не всегда подхватывает классы из новых страниц — после добавления страницы
  перезапустить `npm run dev` (в сборке всё в порядке).
- `noindex` только у `/order/success/` и 404: на остальных он роняет SEO в Lighthouse.

### Подводные камни Astro 7
- Компилятор на Rust строгий: незакрытые теги и невалидный HTML — ошибка сборки.
- `compressHTML` по умолчанию `'jsx'`: пробелы между инлайн-элементами на разных строках
  пропадают — ставить `{" "}` явно.
- Версии и API не выдумывать: сверяться с https://docs.astro.build.

## Процесс
Работа идёт по фазам. После каждой фазы: что сделано, как проверить, коммит — и ждать «дальше».
1. Каркас: Astro, Tailwind, шрифты, макет (шапка, подвал, режим приложения), логотип и PNG, данные, заглушки фото.
2. Главная, меню, карточка позиции, акции.
3. Корзина, оформление, успех, профиль со входом и cookie.
4. Контакты, вакансии с загрузкой файла, политика, 404, PDF-меню.
5. Качество: Lighthouse, Playwright, доступность, правки.
6. Деплой на GitHub Pages через Actions, README.
